# API Reference — Full Endpoint Inventory

Every route mounted in `backend/src/app.js`, grouped by resource. Base URL: `/api`. Generated by reading `backend/src/routes/*.js` directly — this is what's actually wired, not aspirational docs.

**Auth column key**: `Public` = no token needed · `Auth` = valid JWT required (`authMiddleware`) · `Auth+Role(x)` = JWT + `roleMiddleware(["x"])`.

---

## Known Issues

Bugs found and fixed earlier this session, kept here as a record:

1. **`reviewController.deleteReview`** used `review.remove()` — removed in Mongoose 8/9. Fixed to `.deleteOne()`.
2. **`middleware/multer.js handleMulterError`** was an unconditional catch-all, mislabeling every non-upload error app-wide as `"UPLOAD_ERROR"` (400). Fixed to only catch real `multer.MulterError`s, `next(err)` otherwise.
3. **`userController.changePassword`** fetched the user without `.select("+password")` — `bcrypt.compare` always threw since `password` has `select:false` on the schema. This is the `/api/users/change-password` path (used by `/buyer/settings`); `/api/auth/change-password` was always correct. Fixed.
4. **`lib/axios.ts` response interceptor** unwrapped every error into a plain `new Error(message)`, dropping `.response`. Any frontend catch block written as `e?.response?.data?.message` silently fell through to a generic fallback string. Fixed by re-attaching `.response` to the rejected Error.
5. **`GET /api/reviews/:productId`** is not a get-review-by-id route — it's product reviews list. There's no single-review-by-id GET endpoint anywhere in `reviewRoutes.js`.
6. **`otpController` duplicate-signup gaps** — `registerSeller` used to silently overwrite an existing user's role/profile on a duplicate phone/email; `verifyMobileOTP` used to silently log a signup attempt into an existing account. Both now reject with 409 "User already exists...". OTP-send endpoints (`send-mobile`, `send-email`) now also reject duplicates *before* dispatching, so SMS/email credits aren't burned on a doomed signup.
7. **`adminController.deleteUser`** used to hard-delete (`findByIdAndDelete`) with zero cascade — orphaned every `seller`/`user` ref across Products, Orders, Reviews, Conversations, etc. Now soft-deletes (`isDeleted`, cascades `Product.isActive=false` for that seller, kills live sessions in `authMiddleware`). Public product endpoints (`getAllProducts`, `searchProducts`, `getSingleProduct`, `getFeaturedProducts`) also now filter out any product whose populated `seller` is null, covering pre-existing orphaned data.
8. **Duplicate `changePassword`/`updateProfile`** across `authController.js` and `userController.js`. `changePassword` is pure redundancy (same logic, drifted, one was broken). `updateProfile` is legitimately different (seller-field-rich vs buyer-simple) — not a bug, just two modules with overlapping names.
9. **Dev/diagnostic endpoints left mounted in production code** — `productRoutes.js` has 14+ unauthenticated `POST`/`GET` routes under `/*/public/action` paths that mutate product data (add/remove variants, reassign images, seed reviews). These were clearly one-off migration scripts for specific product categories (rice, cement, LED bulbs, conveyor belts, cookies, chemicals, masks) that never got removed. Anyone with the URL can hit them with no auth. Not fixed — flagging for a decision: delete, or gate behind admin auth.
10. **`POST /api/payments/cron/downgrade-expired`** sits behind plain `authMiddleware` (any logged-in user), not an admin role check or a cron-secret header. Any authenticated buyer could trigger subscription downgrades for the whole platform. Not fixed — flagging.
